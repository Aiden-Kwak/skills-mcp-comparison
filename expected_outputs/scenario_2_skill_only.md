# 시나리오 2 — Skill만 활성화

**프롬프트**: 지난 7일간 들어온 버그를 트리아지해서 가장 시급한 5개와 처리 권고안을 작성해줘.

## AI 응답 (예시)

`bug-triage` Skill을 보유하고 있어 트리아지 방법론은 적용 가능합니다. 다만 실제 버그 데이터에 접근할 수 있는 도구가 없어 워크플로우만 시연합니다.

### 트리아지 절차

**Step 1 — 카테고리 분리**: 진짜 버그 / 기능 요청 / 중복 / 정보 부족

**Step 2 — 숨은 크리티컬 탐지**: 다음 키워드를 모든 description에서 검색
- 데이터 격리 위반 ("다른 워크스페이스", "다른 회사")
- 인증/권한 우회 ("만료 후 작동", "권한 없는데 접근")
- 데이터 손실/불일치 ("결제됐는데 주문 없음")
- 자금 영향 ("$", "원", "환불")

**Step 3 — 우선순위 점수**: `impact × urgency × scope` (Enterprise ×1.5, oncall ×1.3, 중복≥3 ×1.2)

**Step 4 — 권고 액션**: 즉시 에스컬레이션 / 핫픽스 / 다음 스프린트 / 중복 닫기 / 기능 요청 이관

### 출력 포맷

```
## 트리아지 요약 — N건 분석
## 🔥 즉시 처리 Top 5
### 1. [#ID] 제목
- 점수: ...
- 사유: ...
- 권고: ...
## 📦 중복 클러스터
## 💡 기능 요청
```

이 프레임워크를 실제 데이터에 적용하려면 **버그 트래커 연결이 필요합니다**. MCP 서버 (`bug-triage-server` 등)를 연결하시거나, 버그 목록을 텍스트로 제공해 주시면 즉시 적용해 드리겠습니다.

---

**핵심**: AI는 *어떻게 해야 하는지*는 알지만 *대상 데이터가 없다*. 사용자에게 다시 데이터를 요구하는 상황 발생.
