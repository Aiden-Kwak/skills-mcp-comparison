# 데모 시나리오 4종

모든 시나리오는 **동일한 프롬프트**로 진행한다.

## 공통 프롬프트

```
지난 7일간 들어온 버그를 트리아지해서 가장 시급한 5개와 처리 권고안을 작성해줘.
```

## 시나리오 1 — 아무것도 없음 (Baseline)

**설정**: Claude Code에 MCP 연결 없음, 커스텀 Skill 없음.

**기대 응답** (요지):
> 죄송합니다. 현재 버그 데이터베이스에 접근할 수 있는 도구가 없어 실제 버그 목록을 조회할 수 없습니다. 일반적인 버그 트리아지 가이드라인은 다음과 같습니다...

**시연 포인트**: AI 단독으로는 사내 시스템에 손도 못 댐. **할 수 있는 일이 없다.**

---

## 시나리오 2 — Skill만 (지식만 있음)

**설정**: `bug-triage` Skill만 활성. MCP 연결 없음.

**기대 응답** (요지):
> 트리아지 프레임워크는 알고 있지만 실제 버그 데이터에 접근할 수 없습니다. 가상의 예시로 워크플로우를 보여드리면... [Step 1~4 설명] ... 실제 적용을 위해서는 버그 트래커 연결이 필요합니다.

**시연 포인트**: AI가 트리아지를 *어떻게 해야 하는지*는 알지만 *대상 데이터가 없다*. **방법론만으로는 부족하다.**

---

## 시나리오 3 — MCP만 (능력만 있음)

**설정**: `bug-triage-server` MCP 연결. Skill 없음.

**기대 응답** (요지):
> [list_bugs 호출] 지난 7일간 23개 버그가 있습니다. severity별로:
>
> - critical 2건: #1 결제 처리 500 에러, #2 DB 응답 시간 30초
> - high 5건: #11 모바일 화이트스크린, #12 Slack 알림 지연, ...
> - medium 10건: ...
>
> 시급한 5개는 critical 2건과 high 중 3건입니다: #1, #2, #11, #12, #15.

**시연 포인트**:
- ✅ 실제 데이터는 가져옴
- ❌ severity 필드만 믿고 정렬 → **숨은 크리티컬 놓침**
- ❌ 중복 신고(#6, #7, #8) 그냥 나열
- ❌ 기능 요청(#9 다크모드)도 같이 섞임
- ❌ "왜 시급한지" 사유 없음, 액션 권고 없음

**데이터는 있지만 분석이 일반적이다.**

---

## 시나리오 4 — MCP + Skill (둘 다)

**설정**: `bug-triage-server` MCP 연결 + `bug-triage` Skill 활성.

**기대 응답** (요지):

```markdown
## 트리아지 요약
- 분석 대상: 23건 (최근 7일)
- 진짜 버그: 18건 / 중복: 3건(1 클러스터) / 기능 요청: 2건
- 🚨 숨은 크리티컬 발견: 3건 (low/medium에서 재평가됨)

## 🔥 즉시 처리 Top 5

### 1. [#1] 결제 처리 500 에러 - 카드 청구는 됐으나 주문 미생성
- **점수**: 67.5 (impact 5 × urgency 3 × scope 3 × enterprise 1.5)
- **사유**: 자금 영향 $47K/24h, Enterprise 3사 영향, 데이터 일관성 문제
- **권고**: 즉시 에스컬레이션 → 결제팀 온콜 페이지. 임시 조치: Stripe webhook 일시 차단 후 수동 정산.

### 2. [#5] CSV export 시 다른 사용자 행이 섞임
- **재평가 severity**: critical (신고자: medium)
- **점수**: 45 (impact 5 × urgency 3 × scope 2 × enterprise 1.5)
- **사유**: 🚨 데이터 격리 위반 — 멀티테넌시 보안 침해. GDPR 영향 가능.
- **권고**: 즉시 에스컬레이션 → 보안팀. 임시 조치: 10K rows 초과 export 비활성화.

### 3. [#4] 관리자 페이지에서 다른 워크스페이스 데이터가 잠깐 보임
- **재평가 severity**: critical (신고자: medium)
- **점수**: 36 (impact 5 × urgency 3 × scope 2 × ×1.2 자체 발견)
- **사유**: 🚨 캐시 키 격리 실패. UI 깜박임으로 보고됐으나 실제로는 데이터 누출.
- **권고**: 즉시 에스컬레이션. 임시 조치: 관리자 페이지 캐시 무효화.

### 4. [#3] 비밀번호 재설정 링크가 만료 후에도 작동
- **재평가 severity**: critical (신고자: low)
- **점수**: 30 (impact 5 × urgency 3 × scope 2)
- **사유**: 🚨 인증 우회. 토큰 만료 검증 실패로 무한 사용 가능.
- **권고**: 보안팀 핫픽스. 임시 조치: 모든 활성 reset 토큰 만료 처리.

### 5. [#2] Production DB 응답 시간 30초 이상
- **점수**: 27 (impact 4 × urgency 3 × scope 3 × oncall ×1.3)
- **사유**: 자동 모니터링 알람, 전체 dashboard 성능 영향.
- **권고**: 이미 in_progress. 진행 상황 보고 요청.

## 📦 중복 클러스터
- **검색 결과 중복 표시** (마스터: #6) — #7, #8을 #6으로 통합. 3건 신고로 widespread 확인.

## 💡 기능 요청 (트리아지 제외)
- #9 다크 모드, #10 차트 export → 제품팀 백로그.

## 📊 컴포넌트별 부담 (최근 7일)
| 컴포넌트 | 신규 | 권고 |
|---------|------|------|
| ui | 6 | 가장 많음, UI팀 핫픽스 데이 권고 |
| api | 5 | webhook/rate-limit 이슈 누적 |
| search | 4 | 중복 클러스터로 실질 1건 |
```

**시연 포인트** (이게 이번 데모의 핵심):

| 내용 | 시나리오 3 (MCP만) | 시나리오 4 (둘 다) |
|------|-------------------|-------------------|
| Top 5 선택 | severity=critical/high만 | 숨은 크리티컬 3건 발굴 |
| #5 CSV export | medium으로 분류, 후순위 | **critical 재평가** — 데이터 격리 위반 |
| #4 관리자 페이지 | medium 그대로 | **critical 재평가** — 데이터 누출 |
| #3 비밀번호 reset | low → 무시 | **critical 재평가** — 인증 우회 |
| #6,7,8 검색 중복 | 3개 따로 나열 | 1개 클러스터로 통합 |
| #9,10 기능 요청 | 우선순위 목록에 섞임 | 분리해서 백로그로 |
| 권고 액션 | 없음 | 매 항목마다 임시 조치 + 담당팀 |

**MCP는 *데이터*를 가져오고, Skill은 *판단 기준*을 적용한다. 둘 다 있어야 비로소 의사결정 가능한 결과물이 나온다.**

## 시나리오별 화면 캡처 가이드

녹화 시 각 시나리오마다 다음 3컷을 잡으면 임팩트가 큼:

1. **프롬프트 입력 화면** (모두 동일한 한 줄)
2. **AI 응답 첫 화면** — 시나리오 1은 거절, 시나리오 4는 표가 보이게
3. **Top 1 항목 줌인** — 시나리오 3은 "결제 500 에러"만, 시나리오 4는 "재평가됨" 배지가 보이는 항목

마지막에 시나리오 1·2·3·4의 응답을 **2x2 그리드**로 한 화면에 배치하면 차이가 한 눈에 보인다.
