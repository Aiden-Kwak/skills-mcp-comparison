# Bug Triage Skill

이 스킬은 버그 목록을 받아서 **진짜 시급한 것**을 골라내는 일을 한다.
신고자가 매긴 severity는 **참고일 뿐 신뢰하지 말 것**. 이유: 고객은 보안 영향을 모르고, QA는 보수적으로 매기며, 자동봇은 임팩트를 모른다.

## 트리아지 절차

각 버그에 대해 아래 4단계를 순서대로 적용한다.

### Step 1 — 카테고리 분리

먼저 description을 읽고 다음 중 무엇인지 판정:

| 카테고리 | 판단 기준 | 처리 |
|---------|----------|------|
| 진짜 버그 | 정상 동작이 정의되어 있고 실패한 케이스 | 트리아지 진행 |
| 기능 요청 | "있으면 좋겠다", "추가해주세요" | 별도 백로그로 분리, 트리아지에서 제외 |
| 중복 | 같은 증상을 다른 사람이 신고 | 마스터 버그로 클러스터링 |
| 정보 부족 | 재현 방법/환경 정보 없음 | 신고자에게 회신 권고 |

### Step 2 — 숨은 크리티컬 탐지

severity 필드와 무관하게 다음 키워드/패턴이 있으면 **무조건 critical로 재평가**:

- **데이터 격리 위반**: "다른 워크스페이스", "다른 회사", "다른 사용자 데이터", "cross-tenant"
- **인증/권한 우회**: "만료 후 작동", "비밀번호 변경 후 세션 유지", "권한 없는데 접근"
- **데이터 손실/불일치**: "결제는 됐는데 주문 없음", "환불 누락", "DB 데이터 사라짐"
- **자금 영향**: "$" 또는 "원" 단위 금액 언급, "환불", "이중 청구"
- **법규/컴플라이언스**: "GDPR", "감사", "개인정보"

> **중요**: 신고자가 low/medium으로 잡았더라도 위 패턴이면 critical. 신고자는 보안 임팩트를 모를 수 있다.

### Step 3 — 우선순위 점수

남은 진짜 버그에 대해 다음 차원으로 점수화:

```
priority = impact × urgency × scope
```

- **impact (1-5)**: 1=불편, 3=기능 일부 사용 불가, 5=서비스 사용 불가/돈 손실/보안
- **urgency (1-3)**: 1=다음 스프린트, 2=이번 주, 3=즉시
- **scope (1-3)**: 1=특정 사용자만, 2=특정 segment, 3=전체

가산점:
- Enterprise 고객 신고: ×1.5
- 자동 모니터링 봇 신고 (oncall-bot): ×1.3 (이미 객관적 증상)
- 중복 신고 클러스터 (3건 이상): ×1.2

### Step 4 — 권고 액션

각 우선순위 버그에 대해 다음 중 하나의 액션 명시:

- **즉시 에스컬레이션**: critical 또는 점수 30+ → 온콜에게 페이지
- **이번 스프린트 핫픽스**: 점수 15~30 → 다음 배포에 포함
- **다음 스프린트**: 점수 5~15 → 일반 백로그
- **중복 닫기**: 마스터 버그 ID 명시
- **기능 요청으로 이관**: 백로그 보드 명시
- **신고자 회신**: 정보 부족 항목

## 출력 형식

```markdown
## 트리아지 요약
- 분석 대상: N건 (창: 최근 X일)
- 진짜 버그: A건 / 중복: B건 / 기능 요청: C건 / 정보 부족: D건
- 🚨 숨은 크리티컬 발견: E건 (severity 재평가됨)

## 🔥 즉시 처리 (Top 5)

### 1. [Bug #ID] 제목
- **재평가 severity**: critical (신고자: low) ← severity가 바뀐 경우만 표시
- **점수**: 32 (impact 5 × urgency 3 × scope 2 × enterprise 1.5)
- **사유**: 한 줄 핵심 — 왜 이게 시급한가
- **권고**: 즉시 에스컬레이션. @보안팀에 할당. 임시 조치: ___
- **연관**: Bug #X, #Y와 동일 컴포넌트

(... 5건 ...)

## 📦 중복 클러스터
- **검색 결과 중복 표시** (마스터: #6) — #7, #8 닫고 마스터로 통합

## 💡 기능 요청 (트리아지 제외)
- #9 다크 모드, #10 차트 export → 제품팀 백로그로 이관

## 📊 컴포넌트별 부담
| 컴포넌트 | 신규 | 처리 권고 |
|---------|------|----------|
| ui | 6 | 가장 많음, UI팀 핫픽스 데이 권고 |
```

## 절대 하지 말 것

- ❌ severity 필드만 보고 정렬 (숨은 크리티컬 놓침)
- ❌ 모든 버그를 똑같이 나열 (=트리아지가 아님)
- ❌ 권고 없이 분석만 (=실행 불가)
- ❌ 기능 요청을 우선순위 목록에 섞기 (=시그널 희석)
